## ✍️ Contributing Documentation

When adding new documentation:

1. **Implementation docs** → `/implementation`
   - Feature name + "IMPLEMENTATION.md"
   - Include: Overview, Features, Database, UI, Testing

2. **Setup guides** → `/setup`
   - Clear step-by-step instructions
   - Include troubleshooting section

3. **Reports** → `/reports`
   - Include date and author
   - Clear summary and recommendations

4. **Guides** → `/guides`
   - User-focused, not implementation details
   - Include examples and screenshots

5. **Update this README** when adding new categories

---

## 🗂️ Documentation Standards

All documentation should include:

- ✅ **Clear title** - What this doc is about
- ✅ **Date** - When it was created/updated
- ✅ **Status** - Complete, In Progress, Outdated, etc.
- ✅ **Summary** - Brief overview (2-3 sentences)
- ✅ **Table of contents** - For longer docs
- ✅ **Code examples** - Where applicable
- ✅ **Next steps** - What to do after reading
